## 1. 設計の考え方

### 1.1 一番大事な利用場面

締切の数分前に、投票アプリと行き来しながら「**どのレースの、どの買い目を、何倍以上なら買うか**」を確かめる。これを最短の操作で済ませるため、次の3つを守る。

1. **起動したら、次に締め切るレースが一番上にある**(S1 既定 = 締切順。締切済みは下にたたむ)。
2. **1タップでレース詳細に入ると、最初の画面内に推奨買い目と必要オッズがある**(S2 の一番上のカード)。
3. **必要オッズは「≧ 32.3倍」の形で、投票アプリのオッズと見比べる数字として一番大きく出す**。確率は補助として小さめに。

### 1.2 情報の優先度(画面全体)

| 優先 | S1 の1行 | S2 締切前 |
|---|---|---|
| 1 | 残り時間(締切時刻) | 推奨買い目 + 必要オッズ |
| 2 | 場名・R番号 | 残り時間 |
| 3 | 本命の枠番 + 1着確率 | 各艇の1着確率 |
| 4 | 堅さ・推奨点数/見送り | 確率上位(券種タブ) |
| 5 | レース名・グレード・日目 | 選手データ(折りたたみ) |

結果が出たあとは「答え合わせ」が目的なので、S2 は **結果 → 推奨買い目(的中の強調) → 確定オッズの期待値 → 各艇** の順に並べ替える(4.2節)。

### 1.3 ボートレースの慣習

- 枠番の色: 1白 2黒 3赤 4青 5黄 6緑(Bのトークン `--c-boat-N-*`)。1(白)は明るい背景で枠線、2(黒)は暗い背景で枠線を付けて輪郭を出す。
- 枠番は **常に数字入りの四角いバッジ** で出す(色だけに頼らない)。組合せは `3-1-4` をバッジ+区切り「-」で並べる。順不同の券種(Phase 2 以降で出す場合)は区切りを「=」にする。
- 印: p_rank 1〜4 に ◎ ○ ▲ △、5〜6 は無印。◎のみ赤(新聞の赤印の慣習。Bの `.mark--1`)。
- 各艇の一覧は **枠番順で固定**(確率順に並べ替えない)。出走表と同じ並びの方が、投票アプリと突き合わせやすい。

### 3.3 数値・時刻の書式

| 値 | 書式 | 例 |

| 2着内・3着内 | 整数(単位は凡例で「%」と示す) | 2着内 47 |
| 組合せの確率(推奨・確率上位) | 1%以上は小数1桁、1%未満は小数2桁 | 3.1% / 0.85% |
| 必要オッズ | JSONの値(小数1桁)をそのまま。1000以上は整数+桁区切り | ≧ 32.3倍 |
| 金額 | 3桁区切り+円。収支は `+` / `−` を付ける | 2,750円 / −300円 |
| 回収率 | 小数1桁の%。100%以上は `▲` を付けて `--c-ev-plus-text`、未満は `--c-danger` | ▲108.7% / 84.0% |
| 期待値(確定オッズ) | 小数2桁。1.00以上は `▲` +緑 | ▲ 1.20 |

### 3.4 堅さ(confidence)

| 段階 | 条件(案) | S1 | S2 |
|---|---|---|---|
| 堅 | confidence ≥ 0.50 | 3本棒 ▮▮▮ +「堅」 | 「堅い」 |
| 中 | 0.35 ≤ confidence < 0.50 | 2本 +「中」 | 「普通」 |

### 5.3 推奨買い目(`.card--emph` + `.pick-row`)

- 見出し「推奨買い目」+ 右に戦略名(例「3連単 確率上位5点」。`strategy.bet_type` と `k` から作る。9章)。
- 説明1行(12px): 「投票アプリのオッズが **必要オッズ以上** なら買い(期待値プラス)」。**締切前だけ** 表示。
- 列見出し(11px): 組合せ / 確率 / 必要オッズ。列幅: 可変 / 64px / 104px。
- 行: 最小高さ52px。組合せは枠番バッジ28px×3。確率13px `--c-text-2`。必要オッズは枠線1.5pxの箱「≧ **32.3** 倍」(数字17px 800)。
- 合計行(背景 `--c-surface-2`): 「5点 · 1点100円で 500円」/ 右「どれか的中 13.3%」(= recommended の prob の合計。同じ券種の組合せは排他なので足してよい)。
- 結果があるとき: 的中した行を `--c-hit-weak` の背景+左4pxの赤帯、必要オッズの下に「✓ 的中 27.5倍」(払戻額÷100)。
- 欠場を含む行: 欠場艇のバッジを薄く+斜線、行背景 `--c-row-muted`、必要オッズの下に「返還」。
- 見送り: 破線の箱「**見送り推奨**」20px + 「買い方の条件に合いません。条件: `strategy.description`」。箱の下に「買う場合は下の確率上位の必要オッズを参考に」。
- 的中の判定: `result.payouts[bet_type]` の `combination` と一致する推奨行。

**必要オッズの見せ方の判断**: 「期待値」という言葉を前に出さず、**投票アプリの画面と同じ「倍」の数字** を、しきい値記号「≧」付きで一番大きく出した。利用者は投票アプリのオッズを見て「32.3以上か」だけを判断すればよい。確率は判断の補助なので小さく灰色。Phase 2 のオッズ入力(S7)は、この行の右に入力欄を出し、入力後は必要オッズの箱を期待値タグ(Bの `.evtag`)に置き換える想定。

### 13.2 オッズの出どころ(ラベル)

| ラベル | 見た目 | 時点の書き方 |
|---|---|---|
| [今のオッズ] | 青の塗り | 「**14:28:40 時点**(公式「14:28現在」)」= `fetched_at`(秒まで)+ `odds_time_label` |
| [キャッシュ] | 青の破線枠 | 「**14:28:10 時点**(32秒前に取得したもの)」= `cached:true` のとき。`cache_age_sec` を使う |

### 13.3 ボタンと状態

| 状態 | パネル | ボタン |
|---|---|---|
| 取得前(`fetch-ready`) | [公開ランク] 14:27時点 …「ボタンで今のオッズを取り、期待値を数値で見られます」 | **[オッズを取る / 30秒ほど]**(青の塗り) |
| 取得中(`fetch-loading`) | 「**オッズを取得中… 12秒**」+「公式サイトから順に取っています(30秒ほど。最大45秒で打ち切り)」+ 進み具合のバー(経過秒 ÷ 30、30秒を超えたら95%で止める)+ 券種の段階チップ(✓済 / 回転中 / 待ち)。`aria-live="polite"` | [取り消し](白地)。取り消したら取得前に戻す |
| 成功(`fetch-ok`) | [今のオッズ] 14:28:40 時点 …「推奨・期待値をこのオッズで計算し直しました」 | [更新 / あと48秒](60秒たつまで無効。残り秒を毎秒更新) → 60秒後は [更新 / 取り直す] |
| キャッシュ(`fetch-cached`) | [キャッシュ] 14:28:10 時点(32秒前に取得したもの) | 同上(キャッシュの元の取得時刻から60秒) |
| 一部失敗(`fetch-partial`) | 黄。「**一部の券種を取れませんでした**」+ 時点 + 段階チップで失敗した券種に × | 同上。取れなかった券種の行は公開ランク(無ければ「—」) |

| 失敗 | 13.4 | 種類ごと |

- 自動取得がオン(S6)なら、S2 を開いたときに条件(締切まで15分以内、60秒以内に取っていない)を満たせば、すぐ「取得中」から始まる。条件を満たさないときは「取得前」のまま。
- 取得中に前後Rへ移動したら、取得は続けて結果をそのレースに保存し(sessionStorage)、移動先では別のパネルを出す。

### 13.4 失敗の表示(`fetch-errors` に一覧)

パネルを赤系(`danger-weak`)または黄系(`warn-weak`)にし、太字の1行目 + 説明 + 必要ならボタン。下の推奨は直前の出どころ(公開ランクなど)のまま。

| 応答 | 色 | 1行目 | 説明 | ボタン |
|---|---|---|---|---|
| 401 unauthorized | 赤 | 🔑 合言葉が違います | 設定の合言葉を確かめてください | [設定へ](S6 `worker-badkey`) |
| 409 closed | 黄 | ⏱ 締切後のため取得しません | 確定オッズは翌日に反映されます | なし |
| 429 daily_limit | 黄 | ⊘ 今日の取得上限に達しました | 上限 300ページ / 日(`quota` があれば数を出す)。明日になると使えます | なし(ボタンも無効のまま) |
| 502 upstream_error | 赤 | ! 公式サイトから取得できませんでした | 時間をおいて再試行してください | [再試行] |
| 503 stopped | 赤 | ■ 今日は取得を停止しています | 公式サイトから制限の応答があったため、今日は取りに行きません | なし |
| 通信失敗・オフライン | 黄 | ⚠ 通信できませんでした | 電波の状態を確かめて、再試行してください | [再試行] |
| タイムアウト(45秒) | 赤 | ⏱ 時間がかかりすぎたため打ち切りました | 公式サイトが混んでいる可能性があります | [再試行] |
| 400 / 403 | 赤 | ! 取得できません(要求の誤り) | アプリの更新や、設定の URL を確かめてください | [設定へ] |

- 429 と 503 は **その日の間、他のレースでもボタンを無効** にし、パネルに同じ文言を出す(余計な要求を送らない)。
- [再試行] も60秒の待ち時間の対象外にしない(直前の要求から60秒たつまでは無効)。ただし 502・通信失敗・タイムアウトは公式に取りに行けていない可能性が高いので、10秒後から押せるようにする(案。フロントと相談)。

### 13.5 S6 の Worker カード

- 位置: 「推奨買い目の決め方」と「どう選ばれるか」の間。見出し「オッズの取得(Worker)」+ 右に [未設定](黄)/ [設定済み](青)/ [要確認](赤)。

- **合言葉**: `type="password"` の入力欄 + [表示] ボタン(押している間だけ表示)。保存後は「••••••••」の読み取り専用欄 + [変更]、下に「保存済み(表示しません)」。保存のタイミングは入力欄から離れたとき。

- 401 を受けたあと S2 の [設定へ] で来たとき(`worker-badkey`): 上に赤の帯「合言葉を確認してください」、合言葉欄を赤枠 + 「✕ 14:28 の取得で「合言葉が違います」と返されました」。

## 15. DA-3・DA-4 のフロント担当への連絡

1. **出どころの優先順位**(手入力 → Worker → 公開ランク → なし)ごとに、行のランク・期待値・推奨の計算を差し替える。パネルのラベルは「今いちばん優先されている出どころ」。手入力が1点だけでも [今のオッズ] と [手入力] を並べて出す。
2. Worker のオッズは sessionStorage だけ(07 9.6)。日付が変わったら捨てる。パネルの「◯秒前」「あと◯秒」は毎秒更新(この部分だけ。画面全体の更新は1分ごとのまま)。
3. 429・503 はその日の間、全レースのボタンを無効にする。401 は S6 の `worker-badkey` 表示へ(状態を持って移動)。
4. 設定の推奨と既定の推奨の差分の文言(12.4)は、フロントで組合せの差を取って作る。
5. ローカル表示の目印(`.localmark`)は `?data=local` か、`data-local/index.json` を読めたときに全画面で出す。
6. S1 の「その場の推奨で最も高いランク」と、S6 の「今日は N R で推奨 · 計 M点」はフロントで計算する。
7. 期待値ランクの境界(A 1.2 / B 1.0 / C 0.8)は、Worker のオッズから計算するときにフロントの定数で持つ(公開JSONのランクと同じ境界。07 3.2 の `EV_RANK_BOUNDS` とそろえる)。
