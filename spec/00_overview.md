# 00 全体像

ボートレース予想ツール(個人用)の仕様書の入口。各担当はまずこのファイルを読み、続いて自分の担当章(01〜05)と `06_tasks.md` を読むこと。

- 作成日: 2026-11-02(PM)
- 対象読者: 収集担当・特徴量担当・モデル担当・エクスポート担当・PWAフロント担当・デザイナー
- 前提方針: リポジトリ直下の `CLAUDE.md` に従う(外部アクセスは1秒以上の間隔で最小限、生データは `data/raw/` でgit管理外、コメントは日本語、commit/pushは指示があるまでしない)

---

## 1. 目的

- 全国24場の当日レースについて、各艇の着順確率と舟券の組合せ確率を出し、スマホで見られるPWAに表示する。
- オッズが手に入る範囲で「期待値 = 確率 × オッズ」を出し、買い目を絞る判断材料にする。
- 過去データでの回収率シミュレーションにより、モデルと買い方の良し悪しを数字で確認できるようにする。
- 利用者は本人1人。ただしリポジトリとGitHub Pagesは公開されるため、公開物は最小限にする。

## 2. データソース調査結果(2026-11-02 実施)

調査で送ったリクエストは、ドキュメント取得を除いて約10件。すべて1.2秒以上の間隔を空けた。

| ソース | URL | 中身 | 期間(実測) | 更新 |
|---|---|---|---|---|
| **Boatrace Open API v1**(以下 openapi) | `https://boatraceopenapi.github.io/api/v1/YYYY/YYYYMMDD.json`、当日分は `.../api/v1/today.json` | 出走表・**直前情報(preview)**・**結果(result)・払戻(payouts)** | 公式表記は2026-01-01以降。実測では2025-12-31も200、2025-01-01は404 | 当日分は約10分ごとに上書き。毎日0時(JST)に前日分を取り直す |
| **Turnmark API v1**(以下 turnmark) | `https://turnmark.github.io/api/v1/YYYY/YYYYMMDD.json` | openapiと同じ構造に、**確定オッズ(odds)が全7券種**加わったもの | 2026-01-01〜前日。当日分は404 | 1日1回(翌日の早朝〜午前) |
| 旧API(非推奨。ただし稼働中) | `https://boatraceopenapi.github.io/{programs,previews,results}/v3/YYYY/YYYYMMDD.json` | 出走表・直前・結果が別ファイルで、スキーマも異なる。オッズは無い | 2016-08-01以降(実測で200) | 約3時間ごと |

重要な訂正: 依頼時には「`data/raw/20261102.json` は出走表のみ」とされていたが、実際には全156レースに `preview` と `result` のキーがある(18:20に取得した時点で結果確定は133レース)。openapi v1 の1ファイルには **出走表・直前情報・結果・払戻がまとめて入っている**。

### 取れるもの・取れないもの

| データ | 過去日 | 当日(レース前) |
|---|---|---|
| 出走表(選手・勝率・モーター等) | ○ openapi / turnmark | ○ openapi(前日夜〜) |
| 直前情報(展示タイム・スタート展示・チルト・部品交換・気象) | ○ | △ openapi。締切の30〜7分前に出るが、API側の遅れが10〜20分あるため、締切前に間に合わないレースがある |
| 結果(着順・進入・ST・決まり手) | ○ | 締切後 openapi |
| 払戻(全7券種) | ○ | 締切後 openapi |
| **オッズ(確定)** | ○ turnmarkのみ(2026-01-01〜) | **× 取得できない** |
| オッズ(締切前・時系列) | × | × |

### オッズが無いことへの対応方針(期待値計算)

1. **バックテスト**: turnmark の確定オッズで期待値と回収率を計算する。確定オッズは実際の払戻倍率と同じ(例: 3連単 1-2-4 のオッズ63.5に対し払戻は6,350円)。ただし「確定オッズを見てから買う」ことはできないので、買い目を確定オッズで決める戦略は楽観的な上限値として扱う(`03_model.md` 6章)。
2. **当日表示(MVP)**: オッズの代わりに **必要オッズ = 1 / 確率**(期待値1.0の損益分岐点)を表示する。利用者は投票アプリで見たオッズと比べて判断する。
3. **当日表示(Phase 2)**: PWA上でオッズを手入力すると、その場で期待値を計算する機能を付ける(ブラウザ内で計算するだけで、外部アクセスは発生しない)。
4. **公式サイトからのオッズ取得(2026-11-03 に利用者が実施を決定。設計と規約の確認は `07_official_odds_and_settings.md`。以下は当初の保留理由で、07 が優先する)**: 技術的には1レース・1券種あたり1リクエストで取れるが、(a) 公式サイトの利用規約上の可否を確認していない、(b) 公開リポジトリのActionsから定期的にスクレイピングするのは負荷と印象の両面で避けたい、(c) 締切直前のオッズは大きく動く、という理由で保留する。やる場合も、本人が選んだレースだけを手動で取り、間隔は1秒以上、券種は3連単のみ、ローカル実行に限る、という案を `06_tasks.md` の未決事項に載せる。
5. **払戻金からの推定**: 払戻金からわかるのは的中した組合せのオッズだけで、外れた組合せのオッズはわからない。turnmark の確定オッズで代わりが利くので、この方法は採らない。

## 3. データフロー

```
[外部]                          [ローカル: git管理外]                                [公開: docs/]
turnmark (過去日・確定オッズ込) ─┐
                                 ├─ src/collect ─→ data/raw/{turnmark,openapi}/YYYY/YYYYMMDD.json.gz
openapi (当日・直前・結果)    ─┘                         │
                                                         ▼
                                         src/features/build_interim
                                                         │
                                 data/interim/ (races / entries / payouts / odds の parquet)
                                                         │
                                         src/features/build_features
                                                         │
                                 data/features/features_{variant}.parquet (1行=1艇)
                                                         │
                         src/model/train ─→ models/{variant}/{model_id}/ (model.txt, meta.json)
                         src/model/predict ─→ data/predictions/YYYYMMDD_{variant}.parquet
                         src/model/backtest ─→ reports/backtest/{model_id}/ (summary.json, bets.parquet)
                                                         │
                                         src/export
                                                         │
                                                         ▼
                                             docs/data/index.json
                                             docs/data/days/YYYYMMDD.json
                                             docs/data/performance.json
                                                         │
                                                         ▼
                                     docs/ PWA (GitHub Pages) ← スマホで閲覧
```

1日の流れ(Phase 1では手動実行。自動化はPhase 3):

```
前日夜〜当日朝  collect(openapi 当日分) → interim → features(pre) → predict(pre) → export
当日 締切前     (Phase 2) collect を10分以上の間隔で再取得 → features(preview) → predict(preview) → export
当日夜          collect(openapi 当日分) → export(結果反映。払戻で的中・回収を計算)
翌日            collect(turnmark 前日分) → interim更新 → export(確定オッズでの期待値を追記)
```

## 5. MVPの範囲

含む:
- 収集CLI(期間をまとめて取得、既に取ったものはスキップ、リトライ、1秒以上の待機)。過去分は turnmark、当日分は openapi から取る
- 生JSON → interim(レース・艇・払戻・オッズ)への変換
- 前日モデル用の特徴量(出走表と、過去の結果から作る集計値)
- LightGBMによる各艇の1着確率。Harvilleで単勝・2連単・3連単・3連複の確率を出す
- 時系列分割での学習と評価(logloss、的中率、回収率シミュレーション)
- 当日分の `docs/data/days/YYYYMMDD.json` と `index.json`、`performance.json` の出力
- PWA: 日付・レース一覧、レース詳細(確率、推奨買い目、必要オッズ、結果)、成績画面。オフラインでも直前に見たデータは表示できること

含まない(Phase 2以降):
- 直前情報を使うモデル、当日の自動再予想
- オッズの手入力、公式オッズの取得(Phase 2。`07_official_odds_and_settings.md`)
- GitHub Actions・GitHub Pages での公開・commit/push(利用者の判断で後回し。当面はローカルで手動実行し、スマホからは同じWi-Fiのローカル表示で見る)
- 2016年からの長期データ
- プッシュ通知

## 6. 用語とID

| 用語 | 定義 |
|---|---|
| 日付 | すべてJST。ファイル名は `YYYYMMDD`、JSONの値は `YYYY-MM-DD` |
| `race_id` | `YYYYMMDD-SS-RR`(SS=場番号2桁、RR=R番号2桁)。例: `20261102-02-01` |
| 枠番 `entry_number` | 1〜6。出走表上の番号 |
| 進入コース `course_number` | 実際に入ったコース。枠番と同じとは限らない |
| variant | `pre` = 前日モデル(出走表のみ)、`preview` = 直前モデル(出走表+直前情報) |
| 券種キー | `win` 単勝、`place` 複勝、`exacta` 2連単、`quinella` 2連複、`quinella_place` 拡連複、`trifecta` 3連単、`trio` 3連複(APIと同じ名前) |
| 組合せ表記 | 順序あり `1-2-3`、順不同 `1=2=3`(APIと同じ。順不同は昇順で書く) |

## 7. 共通の注意(全担当)

- コード値(`*_number`)は名義尺度。`grade_number` は6がPG1で、番号の順と格の順は一致しない。`place_number` は7以上が失格・欠場で、14はフライング。
- 中止レースは、`result.racers.*.place_number` がすべて null。学習と評価から外す。
- キーが無い場合と値が null の場合は、どちらも欠損として同じに扱う(ファイルの生成時期によってキーの有無が違う)。
- 当日のファイルは途中経過。過去データとして確定させるのは、翌日以降に取得したファイルにする。
- 予想は娯楽・研究目的。PWAには「非公式データに基づく参考情報であり、正確性は保証しない」と表示する。
